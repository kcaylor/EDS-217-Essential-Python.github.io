Instructor run-through for Session 2D. Student-facing page: 2d_lists_and_dicts.qmd. Headings below match the markdown scaffold students set up, so everyone stays in the same place.

Total: 25 minutes of coding, 20 minutes of buffer and questions.

Scope discipline

This session teaches lists and dictionaries as objects. It does not teach comprehensions. Comprehensions appear on Day 5, at reading level only. If a student asks, the answer is “that’s a shortcut for exactly this loop, and we’ll read some on Friday.”

Do not use lambda anywhere. It is not in this course.

Framing (1 min)

Say something close to this:

Every time today that you wrote square brackets with column names inside, you wrote a list. Every time you renamed a column, you wrote a dictionary. You already know how to use these. What you don’t have yet is a clear picture of what they are, and that picture is what makes Day 3 onward feel easy instead of arbitrary.

1. Making lists (2 min)

Start with something not about data, so the container is the subject:

Code 
sites = ['Toolik', 'Goleta', 'Santa Barbara']
sites
['Toolik', 'Goleta', 'Santa Barbara']

Points to make:

  • square brackets, comma-separated
  • items stay in the order you wrote them
  • a list can hold anything, including mixed types
Code 
mixed = ['Toolik', 1988, -8.2, True]
mixed
['Toolik', 1988, -8.2, True]

Empty list, since they’ll need it in a moment:

Code 
readings = []
readings
[]

2. Getting things out of a list (3 min)

The zero-indexing conversation. Expect this to be the sticking point.

Code 
sites[0]
'Toolik'
Code 
sites[2]
'Santa Barbara'

Draw the positions on the board under the words. Then the classic error, run it on purpose:

sites[3]

IndexError: list index out of range

Ask them to say why before you explain. Three items, positions 0, 1, 2.

Counting backwards:

Code 
sites[-1]
'Santa Barbara'

Slicing, kept deliberately light:

Code 
sites[0:2]
['Toolik', 'Goleta']

Say: the end is exclusive, you’ll get this wrong sometimes, everyone does, check with len.

Code 
len(sites)
3

3. Changing a list (3 min)

Code 
readings = []
readings.append(4.4)
readings.append(5.1)
readings.append(3.8)
readings
[4.4, 5.1, 3.8]

Points to make:

  • .append() adds to the end
  • it changes the list in place and returns nothing

Run this to make the point stick, because it’s the mirror image of the pandas behavior from this morning:

Code 
result = readings.append(9.9)
print(result)
print(readings)
None
[4.4, 5.1, 3.8, 9.9]

.append() gave you None. The list changed anyway. Compare that with .rename() this morning, which gave you a new DataFrame and left the original alone. Two opposite conventions, and you have to know which one you’re dealing with.

That contrast is the most valuable thirty seconds in this session. Don’t rush it.

You can also replace by position:

Code 
sites[1] = 'Goleta Station'
sites
['Toolik', 'Goleta Station', 'Santa Barbara']

4. Looping over a list (3 min)

Code 
for site in sites:
    print(site)
Toolik
Goleta Station
Santa Barbara

Points to make:

  • site is a name you chose; nothing magic about it
  • the colon, and the indentation, are both required
  • the body runs once per item

Do the indentation error live:

for site in sites:
print(site)

IndexError? No: IndentationError. Say that Python uses indentation the way other languages use braces.

Something slightly more useful:

Code 
for site in sites:
    print(site, len(site))
Toolik 6
Goleta Station 14
Santa Barbara 13

5. Making dictionaries (3 min)

Code 
station_elevations = {
    'Toolik': 719,
    'Goleta': 30,
    'Santa Barbara': 15,
}
station_elevations
{'Toolik': 719, 'Goleta': 30, 'Santa Barbara': 15}

Points to make:

  • curly braces, key: value pairs
  • keys are usually strings; values can be anything
  • the trailing comma is legal and makes edits cleaner

Contrast with a list explicitly:

A list answers “what’s in position 2?” A dictionary answers “what’s the value for Goleta?” Choose based on which question you’ll be asking.

6. Getting things out of a dictionary (4 min)

Code 
station_elevations['Toolik']
719

The error, on purpose:

station_elevations['Bren Hall']

KeyError: 'Bren Hall'

Then the safe version:

Code 
station_elevations.get('Bren Hall')
Code 
station_elevations.get('Bren Hall', 0)
0

Adding and updating:

Code 
station_elevations['Bren Hall'] = 12
station_elevations
{'Toolik': 719, 'Goleta': 30, 'Santa Barbara': 15, 'Bren Hall': 12}
Code 
station_elevations['Goleta'] = 31
station_elevations
{'Toolik': 719, 'Goleta': 31, 'Santa Barbara': 15, 'Bren Hall': 12}

Point to make: same square-bracket syntax adds a new key or overwrites an existing one. There’s no warning either way.

Code 
list(station_elevations.keys())
['Toolik', 'Goleta', 'Santa Barbara', 'Bren Hall']
Code 
list(station_elevations.values())
[719, 31, 15, 12]

7. Looping over a dictionary (3 min)

The default surprises people:

Code 
for key in station_elevations:
    print(key)
Toolik
Goleta
Santa Barbara
Bren Hall

Looping over a dictionary gives you the keys, not the values.

Then both at once:

Code 
for station, elevation in station_elevations.items():
    print(station, 'is at', elevation, 'meters')
Toolik is at 719 meters
Goleta is at 31 meters
Santa Barbara is at 15 meters
Bren Hall is at 12 meters

Two loop variables, because .items() hands back a pair each time. Don’t go deeper than this; they only need to read it fluently.

Timing checkpoints

Elapsed Should be at
5 min end of section 2, indexing done
12 min end of section 4, loops over lists working
20 min end of section 6, dictionary lookup and KeyError seen
25 min section 8, tied back to pandas

If you’re behind at 12 minutes, cut slicing (section 2) and .keys()/.values() (section 6). Do not cut section 8; the payoff is the point.

Common problems

  • Zero-indexing. Draw positions under the items on the board. Come back to it in section 4.
  • Indentation. Trigger the error deliberately rather than warning about it.
  • .append() returning None. Some student will write readings = readings.append(x) and lose their list. Show it before it happens.
  • Curly versus square brackets. If a student writes {} for a list, ask what question they want to ask of it.
