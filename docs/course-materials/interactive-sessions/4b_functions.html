A lightbulb, in the middle of having an idea. MidJourney 5

In yesterday’s end-of-day activity, you wrote this line (or something similar!) three times, changing just a single word each time:

df['Bananas index (kg)'].sort_values(ascending=False).head(10)

Three is something of a magic number in programming: the third time you write something very similar (e.g. that differs by only a single variable), you probably want to start thinking about how to refactor your code to make it more efficient. In addition, repetition of code invites more typos and errors. Copying a line and editing one word is how a good number of data-analysis bugs get written: you change the original, forget to update some of the copies, and now your notebook contains two different answers to the same basic question.

A function is the cure to the tedium and risk of a copy-and-paste lifestyle. You write the work once, give it a name, and then you have a new tool that you and pandas can both use.

By the end of this session you will be able to:

  • define a function with def and hand a value back with return
  • call your function, and store what it gives you
  • give a parameter a default, so the common case is short to type
  • call a function with keyword arguments, so the reader can see what each one means
  • run a function down an entire column with .apply()

def and return

Here is a whole function:

Code 
def celsius_to_fahrenheit(celsius):
    fahrenheit = (celsius * 9 / 5) + 32
    return fahrenheit

Four pieces, and they are always in this order:

  • def announces that a definition is coming.
  • celsius_to_fahrenheit is the name. You choose it, and you should choose it well.
  • (celsius) is the parameter: a name for the value that will be handed in.
  • everything indented under the def line is the body, and return says what comes back.

Running that cell does not convert anything. It teaches Python a new word. To use it, call it:

Code 
celsius_to_fahrenheit(25)
77.0
Code 
water_temp = celsius_to_fahrenheit(12.4)
water_temp
54.32

The indentation is not decoration. Python uses it to mark where the body ends, exactly the way it marked which lines belonged to an if block yesterday.

Note

🐍 A function without return still runs, but it hands back None. If your function seems to “do nothing,” a missing return is the first thing to check.

Code 
def broken(celsius):
    (celsius * 9 / 5) + 32

print(broken(25))
None

Naming things well

The name is most of the value. Compare:

Code 
def f(x):
    return x * 1000
Code 
def ppm_to_ppb(concentration_ppm):
    """Convert a concentration from parts per million to parts per billion."""
    return concentration_ppm * 1000

They compute the same thing. Only one of them will still make sense to you in November.

The line in triple quotes is a docstring. It is optional, it goes on the first line of the body, and Python will show it back to you when you ask for help:

Code 
help(ppm_to_ppb)
Help on function ppm_to_ppb in module __main__:

ppm_to_ppb(concentration_ppm)
    Convert a concentration from parts per million to parts per billion.

Write one whenever the function’s name does not fully explain itself.

Default values

A parameter can have a default, which is used when the caller does not supply that argument:

Code 
def convert_depth(depth, units='meters'):
    """Convert a depth in metres to metres, feet, or fathoms."""
    if units == 'meters':
        return depth
    elif units == 'feet':
        return depth * 3.28084
    elif units == 'fathoms':
        return depth * 0.546807
    else:
        return None
Code 
convert_depth(100)
100
Code 
convert_depth(100, 'feet')
328.084

Notice what is inside that function: the if/elif/else we learned yesterday, doing exactly what it did yesterday. Functions are not a new kind of code, just a wrapper that lets you name code you already know how to write.

Parameters with defaults go last 
def convert_depth(units='meters', depth):   # SyntaxError

Python needs to match the values you pass to the parameters in order, so every parameter with a default has to come after every parameter without one. The error message says non-default argument follows default argument, which is worth recognizing on sight.

Keyword arguments

When you call a function, you can name the arguments instead of relying on their order:

Code 
convert_depth(depth=100, units='fathoms')
54.6807
Code 
convert_depth(units='fathoms', depth=100)
54.6807

Both give the same answer, because naming the arguments makes their order irrelevant. Keyword arguments are something we have been using all week without stopping to name them:

pd.read_csv(url, index_col='entity')
df.sort_values('visitors', ascending=False)
df.dropna(subset=['Measurement'])

index_col=, ascending= and subset= are keyword arguments to somebody else’s functions. Now you know what the equals sign was doing.

The payoff: .apply()

You now have functions that work on one number. Your data has 16,245 numbers in a column.

.apply() runs a function once for every value in a column and gives you back a column of the results:

Code 
plastics['Latitude'].head()
0   -58.428300
1   -51.308200
2   -51.826667
3   -31.696000
4     6.350000
Name: Latitude, dtype: float64
Code 
def classify_latitude(latitude):
    """Label a latitude as tropical, temperate, or polar."""
    if -23.5 <= latitude <= 23.5:
        return 'tropical'
    elif latitude < -66.5 or latitude > 66.5:
        return 'polar'
    else:
        return 'temperate'
Code 
plastics['Latitude'].apply(classify_latitude).head()
0    temperate
1    temperate
2    temperate
3    temperate
4     tropical
Name: Latitude, dtype: object

Read the call carefully, because what goes inside the parentheses is easy to get wrong:

df['column'].apply(function_name)

The function’s name goes inside the parentheses, with no parentheses of its own. You are handing pandas the function itself, not the result of calling it. Add parentheses by mistake and Python will try to call your function with no arguments, and raise a TypeError about a missing argument.

.apply() follows the same rule as almost everything else in pandas: it hands back a new column and leaves the original table alone. Assign it to keep it:

Code 
plastics['zone'] = plastics['Latitude'].apply(classify_latitude)
plastics['zone'].value_counts()
zone
temperate    12275
tropical      3914
polar           56
Name: count, dtype: int64

The zone counts are a real result. Three quarters of this archive was sampled in temperate water, and 56 samples out of 16,245 came from the poles, which probably tells you more about where the research ships went than about where the plastic is.

Note

🐍 .apply() hangs off a column, like .isin() and .fillna() do. The function you hand it should take one value and return one value. Pandas takes care of the repetition.

Writing a function for the work you keep repeating

Here is yesterday’s problem, solved. The top-N pattern, written once:

Code 
def top_n(df, column, n=10):
    """Return the n rows of df with the largest values in the named column."""
    return df.sort_values(column, ascending=False).head(n)

Two parameters without defaults, one with, and three calls to a single definition. The three rankings you wrote out longhand in yesterday’s practice are three lines like these now, and changing your mind about how ranking should work means editing one line instead of three.

Note that top_n hands back a whole table rather than a single labelled column, which is the whole-table form of the two you met yesterday, the one written df.sort_values(...). To get the single-column form back instead, put the column selection inside the function: return df.sort_values(column, ascending=False).head(n)[column].

Key points

  • def name(parameter): opens a function; the indented body is what it does; return is what it hands back. No return means it hands back None.
  • Defining a function runs nothing. Calling it does.
  • Name functions for what they produce. Add a docstring when the name is not enough.
  • Parameters can have defaults, and every defaulted parameter comes after the undefaulted ones.
  • Keyword arguments name the value at the call site. You have been using other people’s keyword arguments all week.
  • df['col'].apply(function_name) runs your function down a whole column. Pass the name, with no parentheses of its own.
  • Write a function the second time you need something, not the fifth.
