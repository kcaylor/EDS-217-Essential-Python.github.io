Over Days 8 and 9 your team builds one notebook. You take the dataset you chose on Wednesday afternoon, walk it through the ten steps, and end with a figure and a claim. Nobody outside your team has seen the data, so on Friday afternoon you introduce it to the class as well as report on it.

This page is the description of the finished thing. The project kickoff covers choosing a team, a dataset and a question. Day 8 and Day 9 carry the hour-by-hour plan.

What you are building

One Jupyter notebook, per team, named Project_<team name>.ipynb.

It is self-contained: somebody who has your notebook and nothing else can restart the kernel, run every cell from the top, and get your figures back. Self-containment matters more than anything else on this page.

It is also the property most often lost, and it is lost in one particular way. You define a variable in a cell, you run the cell, and later you delete it. The variable stays alive in the kernel, so the notebook still works for you. It will not work for anybody else. Restarting and running from the top is the only way to find out.

It is documented: markdown cells explain what each step was for and what it found, and code comments explain anything a reader could not work out from the code.

The analysis uses pandas, numpy, matplotlib and seaborn. The only other import you may need is requests, and only if your file lives in Google Drive rather than at a public URL, which the recipe at the bottom of this page explains. Avoid analyses that need mapping.

The ten steps

Every one of the ten steps appears in the notebook under its own markdown heading, in this order, even where the honest content of a step is one sentence.

  1. Import Data
  2. Explore Data
  3. Clean Data
  4. Filter Data
  5. Sort Data
  6. Transform Data
  7. Group Data
  8. Aggregate Data
  9. Join / Reshape Data
  10. Visualize Data

These are the same ten steps described on The Data Science Workflow.

Step 9 is the one most likely to be short. If your project uses a single table and needs neither a join nor a reshape, write that under the heading and move on. Step 3 is the next most likely: a file that arrives clean has still been cleaned, and “.isnull().sum() is zero in every column and there are no duplicate rows” is that step done properly. A step that is skipped silently is different, because then nobody reading the notebook knows whether the work was unnecessary or merely undone.

What “done” looks like

This is a checklist, not a grading scheme. Nothing here is scored. It is the list I would use if you asked me whether your notebook was finished, so you may as well have it.

The notebook runs.

The ten steps are all there.

The analysis answers a question you wrote down.

The figure carries the claim.

The claim is stated and supported.

Somebody else can read it.

Handing it in

The notebook is due before lunch on Friday, September 11. The whole morning is available to finish in, and presentations are in the afternoon for that reason. There is nothing to submit after class.

The submission form

One submission per team, through the course form. It asks for four things:

  1. Your team name and members
  2. The repository URL
  3. An export of the notebook, either the .ipynb or an HTML export
  4. Your slides, if your team made any. Most teams present from the notebook and upload nothing here.

The form timestamp is the deadline, so submit before you go to lunch rather than after.

  1. Put the project notebook in its own repository, separate from your coursework repository.
  2. Keep the outputs. The GitHub session has you configure nbstripout, which strips figures and printed output from every commit. Stripping output is right for coursework and wrong here, because your figures are the deliverable. Do not configure nbstripout on this repository.
  3. Add a short README.md: the team, the dataset, its source URL, and the question.
  4. Push, then open the repository in a browser. GitHub renders .ipynb directly, so you can confirm in ten seconds that the figures are showing.
  5. Send me the repository URL.

The presentation

Twelve minutes, then three for questions. Present from the notebook itself, and see Day 9 for a walkthrough plan that fits the twelve minutes. Slides are allowed but not expected, and building them is not a good use of Friday morning.

Additional figures are welcome, and you are encouraged to make the notebook engaging to read. Exploratory figures belong under Step 2, where they were actually made.

Finding a dataset

The five tests for a workable dataset are in the project kickoff, and they are worth applying before you commit to anything: one CSV, more than a couple of hundred rows, at least two numeric columns, at least one categorical column, and you can say what one row represents.

It does not need to be environmental data. Be curious.

Loading a CSV from Google Drive

If your file is not already at a public URL, put it in a Google Drive folder in your UCSB account and load it from there:

  1. Save the file to a Google Drive folder in your UCSB account.
  2. Right-click the file and choose Share.
  3. Under General access, change Restricted to Anyone with the link.
  4. Click Copy link, then Done.
  5. Put the code below in the Import Data section at the top of your notebook, with your own link in place of the example.
Code 
import pandas as pd
import requests

def extract_file_id(url):
    """Extract file id from Google Drive Sharing URL."""
    return url.split("/")[-2]

def df_from_gdrive_csv(url):
    """ Get the CSV file from a Google Drive Sharing URL."""
    file_id = extract_file_id(url)
    URL = "https://docs.google.com/uc?export=download"
    session = requests.Session()
    response = session.get(URL, params={"id": file_id}, stream=True)
    return pd.read_csv(response.raw)

# Example of how to use:
# Note: your sharing link will be different, but should look like this:
sharing_url = "https://drive.google.com/file/d/1RlilHNG7BtvXT2Pm4OpgNvEjVJJZNaps/view?usp=share_link"
df = df_from_gdrive_csv(sharing_url)
df.head()
Check this on Thursday morning, not Friday

A Drive link that has not been shared correctly fails silently for everybody except the person who uploaded it. Have a teammate run the loading cell on their own machine on Day 8, before you build anything on top of it.
